# Тренажёр номера: сайт для разучивания хореографии

Проектное решение. 5 августа 2026.

Заказ дословно: сайт по видео номера, чтобы **видеть, что происходит и какое
действие сейчас**; в боевой сцене — **удары в деталях, когда именно они должны
происходить**; референсы ударов копьём из Genshin Impact, подставленные под
тайминг боя, а если не подходят — другие копейные удары; **навигация**;
**видеоплеер**; работает на телефоне, планшете и десктопе.

---

## 1. Что уже есть и почему этого мало

`output/rehearsal.html` (генератор `src/render_rehearsal.py`) уже показывает
текущее движение, следующее, реплику и таймлайн. Три причины, по которым он не
закрывает заказ:

| | |
|---|---|
| **Только звук** | `<audio>` и файловый диалог. Видео номера появилось позже, и посмотреть «что где происходит» на странице нельзя |
| **Бой одной строкой** | у боевой вспышки одно поле `what` на 1.3–2.4 секунды движения. Что такое «полный оборот с копьём, два попадания подряд» — не разучить с одной строки |
| **Нет разучивания** | нет замедления, нет петли на кусок, нет шага по кадрам. Репетиционная страница показывает номер, но не помогает его выучить |

Страница остаётся: она годится как суфлёр на прогоне и весит 40 КБ. Новый
тренажёр — отдельный файл рядом, а не её замена.

---

## 2. Один самодостаточный файл рядом с видео

`output/training.html`. Видео подключается **относительным путём**
`final_v2.mp4` — файл лежит в той же папке. Так работает и из `file://`, и с
флешки, и с телефона: копируется папка из двух файлов.

Данные вшиваются в HTML при генерации, как в репетиционной странице: из
`file://` браузер не даст подгрузить внешний JSON, а сервер поднимать нельзя —
страница должна открываться двойным щелчком.

Если файла видео рядом нет, страница не ломается: показывает файловый диалог и
работает с тем, что выберут (видео или звук — разницы для разметки нет).

**Чего в файле нет намеренно:**

- ни одного кадра из трейлера Genshin. Кадры в `assets/screenshots/` — чужой
  материал, они и в репозиторий не попадают (см. `.gitignore`). Рисунки на
  странице свои: стик-фигуры на SVG;
- никаких внешних библиотек, шрифтов и запросов в сеть. Открывается без
  интернета, в самолёте, за кулисами;
- никакой сборки: ни npm, ни бандлера. Генератор на Python подставляет данные в
  шаблон и пишет один файл.

## 3. Данные: тот же единственный источник таймкодов

```
scenario/timeline.json ──┬─→ звук  (render_audio)
                         ├─→ картинка (render_video ← video_plan + footage ← shots.json)
                         ├─→ хореография (movements.json)
                         ├─→ репетиционная страница (render_rehearsal)
                         └─→ ТРЕНАЖЁР (render_training ← strikes.json)
```

Правило проекта: **ни один таймкод не дублируется.** Движение висит на
`trigger_event`, кадр видеофона — на `anchor`. Тренажёр не вводит исключения.

### Новый файл `scenario/strikes.json`

Разбор боя по долям. У доли нет своего времени — есть событие звука и смещение
от него:

```json
{
  "id": "burst_1",
  "movement": "burst_1",
  "beats": [
    {"role": "windup",  "trigger": "burst1_whoosh", "offset": -0.35, "what": "…"},
    {"role": "swing",   "trigger": "burst1_whoosh", "offset": 0.0,   "what": "…"},
    {"role": "contact", "trigger": "burst1_impact", "offset": 0.0,   "what": "…"},
    {"role": "recover", "trigger": "burst1_impact", "offset": 0.45,  "what": "…"}
  ]
}
```

Сдвинулся удар в сценарии — доля уехала за ним, и переписывать ничего не надо.
Ссылка на несуществующее событие или на несуществующее движение — ошибка
загрузки, а не тихая пустая карточка.

### Слышно пиком, а не началом файла

Ассеты ставятся на таймлайн **началом файла**, а слышны **пиком**. Разница у
быстрого взмаха — 0.376 с; это ловушка, которая в этом проекте срабатывала уже
четыре раза. Исполнителю нельзя показывать время начала файла: он попадёт мимо
на треть секунды и будет прав.

Поэтому `src/peaks.py` замеряет смещение пика внутри каждого ассета через
FFmpeg на этапе генерации, и страница показывает **слышимое** время. Время
файла остаётся в мелком тексте карточки — чтобы будущий я не искал расхождение
с `timeline.json`.

| ассет | пик внутри файла |
|---|---|
| `spear_whoosh_fast` | 0.376 |
| `spear_whoosh_heavy` | 0.050 |
| `spear_armor_impact` | 0.050 |
| `spear_staff_impact` | 0.008 |
| `hit_on_lohen` | 0.032 |
| `spear_grab` | 0.250 |

Кэша нет: замер всех 23 эффектов идёт около пяти секунд, а кэш пришлось бы
инвалидировать по mtime и он стал бы отдельным источником ошибок.

### Что на экране

Короткое человеческое описание кадра берётся из `scenario/shots.json` — новое
поле `на экране` у каждой базы. Времена кадров считает тот же
`footage.resolve()`, которым живёт видеорендерер, а не отдельный список.

## 4. Четыре вида и навигация

Навигация — верхняя панель из четырёх кнопок, состояние в хеше адреса
(`#прогон`, `#бой`, `#движения`, `#как`), цифры `1`–`4` с клавиатуры. Хеш нужен
для того, чтобы «открыть на планшете сразу бой» было одной закладкой.

| вид | что отвечает на вопрос |
|---|---|
| **Прогон** | «что происходит сейчас и что дальше» |
| **Бой** | «какие именно удары и когда» |
| **Движения** | «весь номер списком, куда прыгнуть» |
| **Как тренироваться** | «что мне с этим делать» |

**Плеер общий для всех видов и виден всегда** — прилипает к верху при
прокрутке. Переключение вида не трогает воспроизведение: элемент `<video>` один
и из DOM не переезжает.

### Прогон

Крупно: имя текущего движения, что делать, шкалы скорости и силы, что держать.
Рядом: следующее движение с отсчётом в секундах, текущая реплика, что на
экране. Ниже полоса из трёх сцен с их окнами. Всё это уже проверено на
репетиционной странице — здесь оно повторяется, а не изобретается.

### Бой

По карточке на каждое боевое действие: четыре вспышки, приём удара и копьё в
пол. В карточке:

1. **Таблица долей** — замах, взмах, контакт, возврат. У каждой доли слышимое
   время, что делает тело, и что в этот момент показывает экран.
2. **Стик-фигуры** по доле: рост, стойка, наклон, угол древка в фронтальной
   плоскости. Рисуются параметрически из `pose` в `strikes.json` — авторская
   работа сводится к четырём числам на позу.
3. **План площадки сверху**: куда он смотрит, где стоит противник, какую дугу
   проходит наконечник, куда шаг. Горизонтальный смах во фронтальном виде
   нарисовать нельзя — древко смотрит в зрителя; поэтому вид сверху обязателен,
   а не украшение.
4. **Референс**: что смотреть в игре и в трейлере, со ссылкой. Отдельной
   пометкой — проверено это или сопоставлено мной.
5. **Как разучивать** и **типичные ошибки** — по три-четыре строки.
6. **Кнопка «петля»** — играть только этот кусок, с разгоном 1.5 с до замаха.

### Как тренироваться

Единственный вид со статическим текстом в шаблоне: метод, четыре ступени от
«смотреть» до «в полный размах», что проверять, как пользоваться петлёй и
замедлением, что делать на телефоне. То, что заказчик просил «информацию о
сайте, что мне и как с ним тренироваться», лежит внутри самого сайта, а не в
переписке.

## 5. Плеер: что нужно именно для разучивания

| орган | зачем | клавиша |
|---|---|---|
| пуск/пауза | — | `Space` |
| скорость 0.25 / 0.5 / 0.75 / 1 | связку в 1.3 с на полной скорости не разобрать | `[` `]` |
| петля куска с разгоном | сто повторов одного взмаха | `L` |
| шаг на кадр вперёд/назад | найти кадр контакта глазами | `,` `.` |
| прыжок по движениям | — | `←` `→` |
| полоса с метками | движения серым, попадания красным | клик |

Разгон в петле — 1.5 с до замаха: без него петля начинается с уже начатого
движения, и телу не за что зацепиться. Это дешёвая замена отсчёту «три-два-раз»,
которого в номере нет и быть не может.

## 6. Адаптив

Три раскладки, все на CSS без определения устройства по строке браузера.

| ширина | плеер | контент |
|---|---|---|
| < 640 (телефон) | во всю ширину, прилипший сверху, не выше 34vh | одна колонка, вкладки прокручиваются по горизонтали |
| 640–1023 (планшет) | не выше 40vh | карточки боя в две колонки, если места хватает |
| ≥ 1024 (десктоп) | не выше 46vh, контейнер до 1200px | сетка `auto-fit minmax(340px, 1fr)` |

Ландшафт телефона отдельным правилом по `orientation`: плеер до 62vh, потому
что иначе на 375×812 в повороте от видео остаётся полоска.

Всё, что может не влезть по ширине (таблицы долей), скроллится **внутри своего
контейнера**. Горизонтальной прокрутки у страницы нет ни в одной раскладке.

## 7. Приёмка

**Тесты** (`tests/test_strikes.py`, `tests/test_peaks.py`):

- каждая доля ссылается на существующее событие сценария;
- каждый удар ссылается на существующее движение;
- доли внутри удара идут по возрастанию времени;
- контакт стоит на событии с реальным звуком удара, а не на взмахе;
- окно петли накрывает все доли своего удара;
- `peak_offset` находит пик в синтезированном файле с известным пиком;
- у всех четырёх вспышек есть карточка, и наоборот — карточки без движения нет.

**Браузером**: страница открывается в трёх размерах (375×812, 768×1024,
1280×800), консоль чистая, видео читается, петля попадает в своё окно,
горизонтальной прокрутки нет.

## 8. Порядок работ

1. `src/peaks.py` — замер пика, тесты.
2. `scenario/strikes.json` — разбор боя, `src/strikes.py` — загрузка и проверки,
   тесты.
3. Поле `на экране` в `scenario/shots.json` для десяти баз.
4. `src/training_template.html` + `src/render_training.py`.
5. Прогон тестов, генерация, проверка браузером в трёх размерах.
6. Отчёт в `docs/status/`, ссылка из README, коммит и пуш.

## 9. Открытые вопросы, найденные при замере

Замер боя насквозь по собранному `final_v2.mp4` (прирост яркости для вспышек,
разница соседних кадров для движения) нашёл два места, где звук удара есть, а в
картинке события нет. Оба вне заказа на сайт, оба записаны в тренажёре как есть
и вынесены в отчёт — решение по ним за заказчиком.

| момент | звук | картинка |
|---|---|---|
| первый удар серии 2 | `burst2_impact`, слышно 34.00 | ни вспышки, ни движения: 0.003 при медиане 0.003 |
| удар серии 4 | отдельного удара в сценарии **нет вовсе**, только взмах, слышно 44.98 | процедурная вспышка даёт прирост 0.009 — на глаз ничего |

Тренажёр в обоих местах говорит правду: «экран не помогает, контакт держишь
сам».
