## Требования

- Python 3.12+
- FFmpeg и ffprobe в `PATH` (проверено на 8.1.1)

Библиотек для работы со звуком нет и не будет: обработку делает FFmpeg, Python
только строит команды. Для картинки нужны numpy, scipy и Pillow — видеофон
процедурный, каждый кадр считается арифметикой по массиву 1920×1080.
Кодирование по-прежнему целиком на FFmpeg.

```bash
python -m pip install -r requirements.txt
```

## Запуск

Звук:

```bash
python src/build.py
```

Только проверки, без рендера:

```bash
python src/build.py --check-only
```

Видео со звуком внутри — `output/final_v2.mp4`, несколько минут:

```bash
python src/render_video.py
```

Только кадры-образцы со сводным листом, чтобы посмотреть картинку быстро:

```bash
python src/render_video.py --stills
```

Какого видеоматериала не хватает:

```bash
python src/render_video.py --check
```

Репетиционная страница — `output/rehearsal.html`, дорожка выбирается в браузере:

```bash
python src/render_rehearsal.py
```

Тренажёр номера — `output/training.html`. Видео берёт рядом с собой, поэтому
открывать надо из `output/`, а на телефон копировать оба файла:

```bash
python src/render_training.py
```

Играет он `final_ru_nostrip_titles_logo_fx.mp4` — ровно тот файл, который ушёл
организаторам. Звук страницы сверяется с фонограммой номера при каждой сборке
([src/soundcheck.py](src/soundcheck.py)), и без совпадения страница не пишется:
один раз тренажёр уже играл сборку с английским голосом, и заметить это можно
было только ушами.

Версионируемая копия тренажёра в `site/` — та же страница плюс видео, сжатое до
960×540 (5.5 МБ вместо 43). Её можно открыть прямо с гита на планшете:

```bash
python src/render_training.py --site
```

Голосовые подсказки — две дорожки и печатный лист ориентиров. Времена берутся из
долей `scenario/strikes.json`, то есть из того же источника, что тренажёр:

```bash
python src/render_cues.py
```

`output/rehearsal_cues_v2.wav` — номер плюс голос поверх, для репетиции дома.
`output/stage_cues_v2.wav` — моно, только подсказки, для одного проводного
наушника на сцене; слова в точку контакта в ней нет намеренно, потому что старт
телефона нажимается рукой. `output/cue_sheet.md` — лист: что слышно и за сколько
до удара, что снято из-за наложения и как замерить свой промах старта. Замерил —
пересобери своим числом:

```bash
python src/render_cues.py --start-at 0.95
```

`site/` — единственное место, где производный файл лежит в репозитории.
Иначе страницу нельзя открыть с гита, а без видео рядом она просит выбрать файл
руками. Ролик номера в `output/` при этом не трогается: он остаётся файлом
сдачи. Видео перекодируется только когда оно старше ролика, поэтому после новой
сборки звука достаточно повторить ту же команду.

## Русская озвучка

Реплики и режиссёрские ремарки — `scenario/voices_ru.json`, выбранные дубли живой
записи — `scenario/takes_chosen.json`. Бюджет секунд у реплики не выписан ни там,
ни там: он считается из `timeline.json`, потому что два списка одного и того же
расходятся молча.

Лист записи голосом — что говорить, за сколько секунд и с какой подачей.
Преобразование голоса сохраняет тайминг записи ровно, поэтому секунды в листе —
требование, а не пожелание:

```bash
python tools/eleven_voice.py --sheet --voice lo_v2
```

Нарезка записанных дублей на отдельные файлы. Порог тишины подбирается на каждый
файл свой: у реплик с точкой посередине внутренняя пауза сравнима с паузой между
дублями, и единого порога иногда не существует вовсе:

```bash
python tools/split_takes.py --probe --file "lohen_game.wav"
python tools/split_takes.py --cut --file "lohen_game.wav" --expect 17 --target 2.05
```

Синтез реплик и преобразование живой записи в чужой тембр. Прямой HTTP-клиент, а
не MCP: у MCP-обёртки входные файлы ограничены папкой предыдущего проекта, и
преобразование голоса через неё недоступно в принципе:

```bash
python tools/eleven_voice.py --all --voice lo_v2
python tools/eleven_voice.py --voice lo_v2 --label mysts --take lohen_game=lohen_game_take13.wav
python tools/eleven_voice.py --list-voices
```

Русская версия номера с картинкой. Голосовой стем пересобирается **тем же кодом**,
что обычная сборка, через теневую папку ассетов; три остальных стема и видеопоток
берутся готовыми — они от языка не зависят. Через запятую цепочка приоритета: где
есть преобразование живой записи, берётся оно, остальное синтезом:

```bash
python tools/ru_render.py --voice mysts,lo_v2
```

Два отчёта — по выбранным дублям и по расходу голосов. Собираются из данных, а не
пишутся руками: длины и уровни перемеряются с диска при каждом запуске:

```bash
python tools/voice_report.py
```

Озвучка через Seed Audio на Atlas Cloud — там подача задаётся ремаркой прозой, а
не числовыми ручками:

```bash
python tools/atlas_voice.py --all --dry-run
```

Разбор тренировки по видео — удары, замах, торможение, паузы, мёртвые
остановки. Читает `train/` вместе с подпапками, дубли по содержимому
пропускает, кладёт отчёт с кадрами в `train/reports/<дата>/`:

```bash
python motion/analyze.py
```

Что означают числа и почему метод именно такой — [motion/README.md](motion/README.md)
и [проектное решение](docs/superpowers/specs/2026-08-05-motion-analyzer-design.md).

### Как открыть тренажёр на планшете

| способ | адрес | что нужно |
|---|---|---|
| **GitHub Pages** | `https://rhub1722.github.io/cos-lohen-media-v2/site/` | включить один раз: Settings → Pages → Source: Deploy from a branch → `master` / `/ (root)`. Дальше обновляется само при каждом пуше |
| **Без настроек** | `https://raw.githack.com/RHub1722/cos-lohen-media-v2/master/site/index.html` | ничего, но прокси показывает свою страницу-предупреждение с рекламой, и mp4 отдаёт типом `application/octet-stream` |
| **Локально** | `site/index.html` | скачать репозиторий целиком, открыть файл |

Pages лучше: правильные типы файлов, свой домен, никаких посредников.

`index.html` ищет видео рядом с собой, поэтому открывать надо ссылку на **папку**
(Pages) или файл внутри репозитория, а не отдельно скачанный html. Если видео
рядом не прочиталось, страница один раз пробует запасной адрес на jsDelivr —
это единственный случай, когда она обращается в сеть, и нужен он ровно для
прокси с неправильным типом файла: Safari на планшете `octet-stream` не играет.

Оговорка про запасной адрес: jsDelivr кеширует ветку примерно на полсуток,
поэтому сразу после перекодирования видео он может отдать предыдущую версию. На
Pages и на файле рядом такого нет — там всегда то, что в репозитории.

Через PowerShell:

```powershell
.\build.ps1
```

## Как это устроено

Единственный источник таймкодов — `scenario/timeline.json`. Его читают два
независимых рендерера, и поэтому картинка не может разъехаться со звуком:

```text
scenario/timeline.json ─┬─> src/render_audio.py ─> output/master_v2.wav
                        └─> src/render_video.py ─> output/final_v2.mp4
```

Сборка звука идёт в три шага. Каждый стем рендерится отдельным файлом, четыре
стема суммируются в предмастер, двухпроходный `loudnorm` даёт мастер. Так стемы
и мастер гарантированно согласованы, а не собраны разными путями.

| Модуль | За что отвечает |
|---|---|
| `src/models.py` | схема события и сценария, разбор JSON |
| `src/probe.py` | длительность, частота и каналы файла через ffprobe |
| `src/validator.py` | проверки сценария до рендера |
| `src/filtergraph.py` | построение `filter_complex`, чистые функции |
| `src/render_audio.py` | вызовы FFmpeg: стемы, сумма, нормализация, mp3 |
| `src/measure.py` | замеры мастера: LUFS, True Peak, окна громкости |
| `src/video_plan.py` | состояния палитры и якоря из блоков `video`, без numpy |
| `src/footage.py` | снятый материал и рисованные эффекты поверх тех же якорей |
| `src/render_video.py` | сборка кадра, процедурный фон, мукс со звуком |
| `src/movements.py` | движения исполнителя, привязка к событиям звука |
| `src/strikes.py` | разбор боя по долям, привязка к событиям звука |
| `src/peaks.py` | где внутри ассета лежит пик: событие слышно пиком, а не началом файла |
| `src/render_rehearsal.py` | самодостаточная репетиционная страница |
| `src/render_training.py` | тренажёр: плеер, разбор боя, четыре вида |
| `src/cues.py` | голосовые подсказки: слово на роль доли, разбор наложений |
| `src/render_cues.py` | две дорожки подсказок и печатный лист ориентиров |
| `src/voice_lines.py` | русские реплики, бюджеты секунд, лист записи голосом |
| `src/build.py` | точка входа и CLI |

## Тесты

```bash
python -m pytest -q
```

Тестами покрыты чистые функции: разбор сценария и блоков `video`, валидация,
построение графа фильтров, привязка движений. У картинки тестами закрыто ещё и
поведение во времени — предохранитель на центральную полосу, длина белой
вспышки, остановка движения на финальном якоре: это ошибки, которых на
стоп-кадре не видно.

Звук проверяется замерами через `loudnorm` и `ffprobe`, а не юнит-тестами.

## Что на выходе

`output/master_v2.wav` — 48 кГц, стерео, 24 бита, ровно 60.000 с, −16 LUFS,
−1.5 dBTP. Рядом `master_v2.mp3` 320 kbps для прослушивания, четыре стема,
`render-report-v2.json` с замерами и `final_v2.mp4` со звуком внутри.

Содержимое `output/` не версионируется: оно полностью воспроизводится сборкой.

## Ограничения проекта

- AI не микширует: Python для конфигурации, FFmpeg для обработки и кодирования.
- Исходные WAV не изменяются, производные пишутся в новые файлы.
- Без pydub и звуковых библиотек. Для картинки — numpy, scipy, Pillow.
- Все пути относительны корня проекта.
- Клиппинга нет.
- Отсутствующие звуковые файлы не выдумываются.
- Успех не объявляется, пока мастер реально не создан.
